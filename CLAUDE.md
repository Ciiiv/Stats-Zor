# Stats-Zor: notes for Claude

A static NHL analytics site (skaters and goalies) on GitHub Pages: https://ciiiv.github.io/Stats-Zor/
No server, no database, no AI at runtime. A nightly GitHub Actions job builds JSON into `data/`; the pages read it in the browser.
Read `README.md` (structure, pipeline, how to run) and `about.html` (every formula and its limits) before changing anything.

## Working with the owner
- If a message says "no code", "just a question" or "let's talk first", answer only. Don't edit files, publish or push until asked.
- For big or judgment-call changes (model weights, new sections), lay out the plan or options first and let the owner pick.
- Explain results in plain hockey terms, with real player examples, not code details.
- Commit to `main` only when asked to build something. Don't leave extra branches behind.

## Hard rules
- **Never scrape PuckPedia** (its terms forbid it). Contract data isn't in the site; cap hits are typed in by the user and stay in their browser (`localStorage` key `sz-cap-{playerId}`).
- **MoneyPuck data is non-commercial use with credit to MoneyPuck.com.** Keep the credit in every page footer and in the README. The bulk files on `peter-tanner.com` are MoneyPuck's (Peter Tanner runs MoneyPuck).
- Pipeline scripts use the **Python standard library only**. Front end is vanilla JS + hand-written SVG, no frameworks or chart libraries.

## Conventions
- **Seasons are start years:** `2025` = 2025-26. A new season starts September 1 (`current_season()`).
- **Age** is as of February 1 of the season.
- **Percentiles** are within position group only (F, D, G), flipped where lower is better, so blue is always good.
- **Player names come from `data/index.json`** (NHL spellings with accents). MoneyPuck's season files drop accents and use other spellings (Raty, Lafrenire, Alex Nylander), so `loadSeason` in app.js and goalies.js swaps in the index name; sidebar and teams-page strips do the same.
- **Game-by-game strips** (teams page lineup and goalie usage) draw at their natural size (`svg.strip` in styles.css: `width:auto; max-width:none`), never stretched to the panel width, so a new season with a few games stays small instead of blowing names and squares up; long seasons scroll sideways inside `.scroll`.
- **Goalie pools use team games**, not the goalie max: `team_gp` in the goalie season files (no goalie plays 82).
- **Cache busting:** pages load `styles.css?v=…`, `theme.js?v=…`, `common.js?v=…`, `app.js?v=…`, `goalies.js?v=…`, `trade.js?v=…`. Bump the `v` (a timestamp like `202611150400`) in every page that loads a file you changed.
- **When a calculation changes, update its section in `about.html`** (and the README if a setting or script changes).
- Every section head links to its `about.html` anchor with `<a class="how">`. Sections render through `safe(id, fn)` so one failure doesn't break the page.
- Copy style on the pages: plain sentences, no jargon without a glossary entry, state limits honestly (the `details.lim` boxes).

## Testing
- **The cloud workspace usually can't reach MoneyPuck, peter-tanner.com, the NHL APIs or the live site.** Don't assume the scripts can run against real data locally.
- **Real data:** what works is a temporary branch with a workflow triggered `on: push` that runs the needed scripts and commits `data/` back to that branch with `[skip ci]` in the message (needs `permissions: contents: write`). Fetch it, inspect, then copy the files onto `main` and delete the branch (the owner may need to delete it on GitHub; the proxy can block branch deletion). Workflow artifact downloads are blocked by the proxy, so commit the data instead.
- **Fake data:** `STATSZOR_FIXTURES=/path` makes `fetch()` read files named by the sha1 of each URL. Good for checking that the code runs, not for checking numbers.
- **Front end:** serve the repo with `python -m http.server` and drive it with Playwright (preinstalled). Check for console errors, look at screenshots, and check `document.documentElement.scrollWidth` at 390 px wide (no sideways page scroll on phones; wide tables go in `.scroll`).
- Trigger the nightly job: `gh api -X POST repos/Ciiiv/Stats-Zor/actions/workflows/update-data.yml/dispatches -f ref=main -F 'inputs[full]=false'`; read logs with `gh run view {id} --log`.
- Sanity-check against known numbers, e.g. MoneyPuck goalie shots on goal and goals match NHL `shotsAgainst` and `goalsAgainst` exactly.

## Git in this environment
- Shallow clones: `git -c fetch.negotiate=true fetch origin main --depth=5`, rebase onto `origin/main` before pushing (the nightly bot commits data), push with `git -c push.negotiate=true push`.
- Don't commit `__pycache__` (it's in `.gitignore`).

## Decisions already made (and why)
- **Value model** is Stats-Zor's own, simple and fully shown on the methods page: skater goals above replacement scaled down for shared on-ice credit; wins = goals ÷ 6; a win is priced from the skater (88%) or goalie (12%) share of the cap.
- **Goalies get half credit** for goals saved above replacement (a season is roughly half luck). That puts goalies at about 13–15% of all positive wins, close to their cap share. Dollar worth barely depends on this weight.
- **Goalie projections** keep `shots ÷ (shots + 3,000)` of a goalie's edge over the league-average goalie (three seasons of shots), and are valued at his own workload (games per season, up to 65). One hot season shouldn't price like a proven elite goalie; the owner wanted "only valued if they're great" to hold. Skaters keep their simpler 3-season projection.
- **Value card** shows worth for the selected season and over the last 3 seasons (wins per 82 blended 3/2/1 × games, priced at the selected season's win; goalies use wins a season), because one season can swing a lot (Makar 2025-26).
- **Isolated impact** (`build_impact.py`, skater page Part 1): a ridge regression over every 5v5 shift since 2010-11 (NHL shift charts + play-by-play for faceoff zones and score, MoneyPuck shot xG). Each stint is two rows (each team attacking), weighted by time, with each skater's offense and defense plus home, zone start and score-state terms. The penalty is applied to skaters only. Single-season and three-season fits. Shown next to relative, not instead of it. Rink scorekeeper bias is not adjusted for: discussed and skipped (MoneyPuck already arena-adjusts shot locations, so the leftover effect is small).
- **5v5 in the value model** blends isolated and relative (`ISO_WEIGHT`, chosen by the forecast test in `data/impact/test.json`, which scores against next season's on-ice and relative results so neither method is favoured). Isolated numbers are stretched per season and position to the spread of 0.5 × relative, so 5v5 keeps the same share of value and only who gets the credit changes. The test (15 season pairs, Nov 2026) put 0.67 best on the average of both targets (isolated alone wins on next on-ice, relative alone on next relative). The test reruns nightly; if `best_isolated_weight` moves for good, update `ISO_WEIGHT` and the about page. Seasons before 2010-11 use relative only. One official number everywhere; the Value card's "5v5 method" box is read-only.
- **Isolated impact v2 (Nov 2026, all tested on real data before switching on):** one-season fits start from `PRIOR_KEEP` = 0.75 of last season's estimate (200+ minutes), and players with no usable last season from a box-score (SPM) estimate (`PRIOR_SPM`); best of 8 versions, about 10% better at predicting next season than starting at 0 (0.342 vs 0.312). Three-season fits still start at 0. Same regression also on goals and unblocked shot attempts (display only, `goff`/`gdef`/`foff`/`fdef` and 3-season versions). Separate 5-on-4 fit (`LAMBDA_PP` = 80): `pp`/`pk` with `ppt`/`pkt` minutes. Value model: `ISO_WEIGHT_PP` = 0.5 (isolated PP is relative to average, on-ice PP is a level, so the stretched isolated number is re-centred on the group's mean on-ice level before blending; without that, PP1 players lost credit wholesale, fixed Nov 17) (PP blend predicted slightly better, 0.394 vs 0.389), `ISO_WEIGHT_PK` = 0 (isolated PK predicted worse; PK barely repeats year to year). After the switch the 5v5 blend test slightly preferred 0.75 over 0.67 (0.3462 vs 0.3456); kept 0.67 as noise. Rerun tests with `python scripts/build_impact.py --prior-test --pp-test` (rebuilds every season; run on a temporary branch, about 35 minutes).
- **Finishing** (`finishing_credit` / `FIN_K` in `build_value.py`, Nov 2026): three-season goals above expected per shot × 3-season shots ÷ (shots + K) × this season's shots; K = 400 forwards, 2,000 defensemen (fit from year-to-year carry-over since 2008: forwards 28% one season / 53% three, defensemen 7% / 15%). Beat the old 0.5 × gax by 11% (F) and 14% (D) at predicting next season; for D even zero beat half. The owner chose it for both positions, with a read-only "Finishing method" box on every Value card (what happened / old half rule / used; `fin_actual` in value.json) and a note on defensemen whose 3-season actual minus credited finishing is 6+ goals (Makar, Dahlin, Chychrun, Bouchard…), explaining that D finishing barely repeats and chance creation counts in full.
- **Player cards** carry a team-color edge (`TEAM_COLORS` in `common.js`, historical codes included), a team badge and the current jersey number (`num` in `rosters.json`, shown only when the card's team is his current team; otherwise a small "Now #7 · VAN" line, `nowLine` in `common.js`). No logos or photos (decided).
- **Teams page** (Nov 2026, Phase 1): team + season + recent window (10/20) pickers; card (5v5 xGF% and rank, last-N, GF%, skaters used, usage-flag counts, head coach); rolling 5v5 xGF% trend (until game N the window borrows the end of the franchise's previous season, drawn lighter over a shaded band; with no previous season, season-to-date from game 3; goals dotted; coach changes marked); lineup strip (slot each game from that night's 5v5 ice time, same rule as build_usage; PP view; last 20 by default on phones); deployment table = the skater page's team card plus "Last N" slot with ↑/↓ at 0.75+ of a slot. Owner's rule: recent views describe only and never feed value or fit. Coaches come from the NHL right-rail `gameInfo.headCoach`, one-or-two-game runs folded in (interim fill-ins); `--coach-budget` 1,500 games a run, newest season first. Phase 2 (built Nov 2026): "Who carries the team" (wins above replacement by age from value.json; traded players count wins × games with this team ÷ season GP, same split for every team's ranks; tiles: total wins + rank, share from 25 and under, top-3 share, games-weighted age); pay vs. value table where cap hits are typed **on the teams page only, kept in memory (`TP.caps`), cleared on refresh, never reading or writing player-page or trade-machine cap hits** (owner's choice: each page has its own); value compared = the player's season `worth` (full-season rate, same as his player page), not prorated. "Goalie usage" (start/relief strip from `data/goalies/games/{y}.json`, starts, record, sv%, saves above expected = xGA − GA, back-to-back starts, recent starts). "Season by season" from `data/teams/history.json` (built every run by `write_history()` in build_usage.py: per season per team gp, t5, xGF, xGA, GF, GA, coaches), chart shaded by the coach who finished each season, most valuable = top war on the team (skater or goalie). "Used about right" per season only via a button (about 30 MB, reuses `deployData()`; owner said no second copy of the fit logic in Python, slow phone loads are fine with a notice).
- **Box score detail and faceoffs** (Nov 2026): `build_box.py` → `data/box/{y}.json` from NHL stats reports (summary, scoringpergame, realtime, shootout, faceoffwins; zone faceoffs from 2009-10). Player card block `boxHTML()` in app.js: G/A with EV-PP-SH and A1-A2, points by situation, shots of attempts, sh% vs expected (MoneyPuck `gax`), penalties drawn-taken (MoneyPuck) + PIM, faceoffs (50+ draws) overall/own zone/offensive zone; "for the record" line (GWG, OT, empty-net, shootout, plus/minus) as plain counts labeled mostly luck. Descriptive only, never in value. Under it a "Big nights" line (`streakHTML()`, Nov 2026): hat tricks, multi-point and 4+ point games, longest point / goal streak, longest pointless run, live streaks (current season, 2+ games), and a career line (labeled "Since 2008-09" if he started earlier) from `data/streaks/{y}.json` and `career.json` (`build_streaks` / `write_streak_career` in build_usage.py, from the MoneyPuck game-by-game file it already reads; games missed don't break streaks; streaks don't carry across seasons). Matched NHL game logs exactly on 30 player-seasons. Sidebar "Faceoffs" tab (`fo` in GEM_BUILD) with four lists on the filter buttons (Best 1,500+ draws, Own zone / Struggles / Offensive 300+ in the zone, three seasons, players active this season). Sidebar names come from the search index (MoneyPuck season files drop some accents).
- **Special teams tab** (Nov 2026, `st` in GEM_BUILD, filter buttons like Faceoffs): three seasons, active this season, ranked within position. Power-play heavy (100+ pts, PP share of points top 20%, chip = 5v5 points/60 percentile vs all regulars with 2,000+ EV min); 5v5 scorers, little PP (2,000+ EV min, EV pts/60 top 30%, under 1:30 PP a night); PP struggles / Penalty kill / PK struggles (owner chose team-relative, Nov 2026): his on-ice pp_xgf60 / pk_xga60 minus the time-weighted rate of his team's other players on that unit each season, combined by his minutes; 300+ minutes; bottom / top / bottom quarter within position; chip = his rate and team's. Raw rates were mostly team effects (Detroit's whole PK, Florida's whole PP). Big number: PP share % for Power-play heavy; within-position percentile (1st-99th) for the rest. Points from data/box, minutes and pk_xga60 from MoneyPuck season files. Descriptive only.
- **Puck play tab** (Nov 2026, `puck` in GEM_BUILD, filter buttons): `data/puck/{y}.json` from build_usage.py (`build_puck`, MoneyPuck game-by-game, situation all): per skater toi and tk/gv/hit/blk raw and arena-adjusted (`_a`: each game ÷ that arena's season factor = arena rate both teams / league rate, pulled to 1 by home games/(home games + `PUCK_K` 20)). Lists over three seasons, 1,500+ min, within position: Takes it away (tk/60 top 20%), Careful / Loose with it (tk share of tk+gv, 60+ events, top / bottom 20%), Shot blockers, Physical. Tested before building (8 seasons): arena factors 0.4-1.8 for tk/gv through 2023-24 and stable by arena, ±10-15% since 2024-25; hits/blocks repeat r≈0.9, tk/gv r≈0.6 (road-only worse, 0.45, so arena adjustment instead); gv barely tied to points (r 0-0.28). Descriptive only.
- **Discipline tab** (Nov 2026, `disc` in GEM_BUILD, filter buttons): `build_disc.py` → `data/disc/{y}.json` (NHL skater/penalties report + game-center play-by-play per game, games remembered in the file, `--budget` 1,500 a run newest first, `v` 2). Minors drawn/taken (`md`/`mt`) leave out scrum calls (roughing, fighting, unsportsmanlike, misconducts) because they usually go both ways; with them in, the drawn list was scrum players. Lists, three seasons, within position: Draws penalties (md/60 top 20%, 1,500+ min), Undisciplined (mt/60 top 20%), Clean physical (arena-adjusted hits/60 top 30% from data/puck and mt/60 below the median), Fighters (60+ GP, 3+ fights; count + per 82, chips instigators, misconducts "any reason", roughing). Tested on ten seasons: md r 0.64, mt 0.57, fights 0.74, roughing 0.53, misconducts 0.34. No fight wins (no official record; don't scrape fan-vote sites). Descriptive only.
- **Scheduled check-ins** (cloud, report-only, push notification): "Stats-Zor weekly health check" Mondays 4:59 pm ET (nightly runs, data freshness, test drift, missing games) and "Stats-Zor September upkeep check" every Sept 3 (paused workflow, cap figures, and the yearly value-vs-standings rerun: temporary branch for `fetch_standings.py`, then `check_value_vs_standings.py`, a new row in the "Results over time" table of docs/CHECKS.md and the updated `data/checks/standings.json` committed to main; the owner deletes the branch). The weekly check notifies only when something needs attention.
- **NHL EDGE stats** (speed, shot speed) describe style, so they feed similarity and a "slowing" trend, not value.
- **Deployment fit** is judged three ways (5v5 results, overall value, against his role).
- **Competition and linemates** (`competition()` in `build_impact.py`, `comp` in `data/impact/{y}.json`, shown at the top of Role & fit): % of 5v5 time vs the opponent's top line (2+ of its 3 most-used forwards that game) and top pair, and time-weighted isolated net of opponents and teammates. Descriptive only; it doesn't change value (isolated impact already accounts for both). Older seasons are backfilled newest first, a few a night. Games whose NHL shift charts can't be read are left out and listed in `data/impact/missing.json` (per season: date, teams, reason, count by team; `write_missing` in build_impact.py), which the weekly health check reads. Competition varies far less than linemates.
- **Trade machine contracts:** the site never knows contracts. Years left after this season are blank until the user types them (blank = this season only, flagged). Cap hits are in $M; dollar amounts convert. Trades are not saved on refresh, on purpose (the owner prefers a clean slate).
- **Team control:** RFA seasons are estimated with the UFA rule (27 by June 30 or 7 accrued seasons; accrued ≈ 40+ NHL games, 25+ for goalies) and added through a checkbox that auto-sets but can be overridden. RFA seasons are assumed paid fair value, so they add wins but no surplus.
- **Team plans** (trade machine): No preference (default, pure value) / Contending (next 2 seasons full, then −15% a season) / Bubble team (−7.5% a season) / Rebuilding (×0.5 this season, ×0.8 next) per side, weighting wins by season (`MODES` in `trade.js`). A plan describes what a team cares about, not its standings. No-preference verdicts stay the headline; plans add a per-team row. Pick wins are spread over 3 seasons from 2 years after the draft. Dollar figures on assets are totals over the seasons counted; real salary and assumed RFA pay are shown separately. The trade page header holds the team and plan pickers plus a live score card (one tap-to-expand line on phones); the intro is one line linking to `about.html#m-trade`.
- **Small-sample skater projections** (`SKATER_GAMES_FULL` = 150 in `build_value.py`): under 150 games in the 3-season window, keep games ÷ 150 of the gap to an average regular at the position. The owner chose this over full shrinkage (K=60, best in the 2011-26 backtest) because full shrinkage also marks established stars down about 15%. Known gap, discussed and parked: the model prices every win the same, so top stars' fair value (~12–15% of cap) sits below the 2026 market (Makar $20.4M, Carlsson $18M, Kaprizov $17M). Decided: no star-premium "market price" (it would be set by hand without contract data; the owner prefers every number to come from data). The gap is explained in the contract limits note and visible through the cap-hit box. 
- **Skater age curve is fitted from data** (`fit_age_curve` in `build_value.py`, nightly): next-season ÷ this-season wins per 82 by age band and position, players chosen by being 1+ win regulars the season before (avoids regression bias), leavers count as replacement, bands need 100+ players, never rises after falling. Backtest beat the old hand-set curve (Nov 2026). No special rule for elite players: the data showed stars don't age better in percentage terms. Goalies keep hand-set `AGE_MULT_G`.
- **Scouting lists sidebar** (`renderGems` in `common.js` renders any list, with tabs; skater lists are the `GEM_BUILD` builders in `app.js`, the goalie list is `renderGemsGoalies` in `goalies.js`; all computed in the browser from data already loaded). Pages wrap `<aside id="gems">` and `<main>` in `.layout`: a sticky right column at 1400px and wider, a tap-to-open line above the content otherwise. Owner's rule: no small samples (three-season isolated numbers need 1,500+ five-on-five minutes, `GEM_MIN_TOI3`). Skater tabs, in the owner's order:
  - Box score (the original idea: elite work in bad situations without full credit): three-season isolated net top 20%, points per game not top 10%, plus low points (bottom half) / weak linemates (bottom third) / tough minutes (top fifth opponents' quality); sorted by isolated pct minus points pct.
  - Carrying: isolated net top 20%, points top 40%, team's 5v5 xGF% without him (`off_xgf60`/`off_xga60`) or linemates bottom third; sorted by isolated + points − without-him − linemates pct. Can't prove he'd be better elsewhere.
  - Shutdown: three-season isolated xGA/60 top 20% plus top 40% opponents' quality or top-line time; PK chip at 1:30+ a game. The competition part keeps out sheltered depth players.
  - Breakout: age 24 or under (careers.json birth), single-season isolated net top quarter with 800+ minutes, up 0.15+ xG/60 on last season (500+ minutes).
  - Bounce: goals above expected (`gax`) at most −4 × season progress, after +2 or more over the two previous seasons (40+ GP each).
  - Big minutes: ice time top quarter, three-season isolated bottom 20%. Not "overpaid" (no contract data).
  - Goalie tabs (`GEM_BUILD` in `goalies.js`; shot minimums `GEM_SA` 1,000 this season scaled by progress, `GEM_SA3` 2,500 over three seasons, because a goalie season is about half luck): Little help (sv% above expected top 20% plus losing record / tough shots / busy nights), Stealing games (top 20% saves, record top half, team xGA/60 or xG per shot top third), Danger specialist (three-season high-danger sv% above expected top 20%, 300+ HD shots), Breakout goalie (age 27 or under, top third, up 0.8+ on last season with 500+ shots), Due for a bounce (≤ −0.5 now after +0.3 over the two seasons before, 800+ shots each), Heavy workload (starts top quarter, three-season saves bottom 20%). Goalie lists are often short (2-7 names); that's expected.
  - Leaders (`lead`, Nov 2026, last tab on both pages): plain leaderboards, descriptive only, filter buttons pick the list and `GEMS.opt` toggles (`cfg.toggles` rows in `renderGems`; `cfg.rebuild` makes list buttons rebuild) pick Best/Worst, Forwards/Defense and This season/3 seasons. Skaters (`LEAD_*` in app.js): 5v5 xG share (chip vs. teammates off ice), Creates (ixG/60), Suppresses (xGA/60, chip vs. teammates); 600+ 5v5 min × season progress (floor 150) or 1,500 over three; Forward lines / D pairs from `data/lines/{y}.json` (chip vs. team 5v5 share from `data/teams/{y}.json`), 300 min × progress (floor 100) or 400 over three, combos that played together this season; clicking one opens player 1 with player 2 as B (`pickGem(id, id2)`). Goalies: saves above expected (xGA − GA) and high danger measured against the league-average goalie that season (MoneyPuck HD xG runs ~30% above actual HD goals, so raw HD "above expected" was positive for everyone).
  Each list carries a `unit` line saying what the big number is (a percentile among regulars at the position, except the bounce tabs: goals or save % points vs expected). An ordinal big number (96th) is labeled "… percentile" under it in every list (`renderGems`). Top 10, show more, F/D filter, click opens the player on the same season. New lists only need a builder in `GEM_BUILD` and an entry in `GEM_TABS`/`GEM_TITLE`.
- **Shot maps** draw smoothed by default (`smoothHeat` in `common.js`: Gaussian over the 5 ft cells, σ 7 ft, sampled every 1.25 ft into a canvas image in the SVG), with a Cells toggle. A `themechange` event (from `common.js`) redraws them.
- **Prospects** are valued by draft slot (decaying 15% a year since the draft); from 40 NHL games their own projection blends in by games played (100 = all NHL record). CapFriendly is gone and PuckPedia can't be scraped, so none of this uses contract data.
- Defaults: skater page Seider vs. Makar; goalie page Vasilevskiy vs. Shesterkin. Both open on the last complete season until the current one passes 41 team games.

- **Widespread, still free:** add a footer line "Not affiliated with or endorsed by the NHL or its teams" (no page says it now); decide on a license file (none now, so by default no one may reuse the code; the data keeps its own rules); add a way to report problems (GitHub Issues link or email); fix known data gaps first (e.g. missing current-season games) so numbers match NHL.com.
- **Paid (ads, subscriptions):** MoneyPuck is non-commercial only and its xG drives most of the site, so get MoneyPuck's permission or a paid arrangement first, or build our own xG model from NHL play-by-play. The NHL's public feeds aren't licensed for commercial use and its terms of use restrict it. GitHub Pages' rules don't allow running a business mainly on Pages, so move hosting.
- **Load:** fine for a long while. The site is about 74 MB (mostly `data/`); Pages' soft limits are 1 GB size and 100 GB traffic a month; visitors only download the files they view, and with no server there's nothing to crash.
- **Privacy:** no accounts, no tracking, cap hits stay in the browser. If visitor counts are ever added, use a privacy-friendly counter and add a one-line privacy note.
